## 1. Физическая организация данных
* **Страничная структура:** Данные хранятся в файлах (`.mdf`, `.ndf`), разбитых на страницы по **8 КБ** (минимальная единица чтения/записи). Страницы объединяются в экстенты по **64 КБ**.
* **Построчное хранение:** Запись хранится на странице целиком (кроме больших полей LOB). При чтении даже одного атрибута с диска считывается вся строка.
* **Анализ ввода-вывода:** Включение статистики логических и физических чтений страниц:
```sql
SET STATISTICS IO ON;
SET STATISTICS TIME ON;
SELECT * FROM SeriesValues;
```

## 2. Индексы: B-Tree и B\*-Tree
Индексы оптимизируют поиск до O(log(N)) вместо полного сканирования таблицы O(N).
* **Кластерный индекс (Clustered):** Листовые узлы являются самими страницами с данными. Может быть только один на таблицу.
* **Некластерный индекс (Non-Clustered):** Листовые узлы хранят ключи и ссылки на данные (значение кластерного ключа или физический адрес).
* **Покрывающие индексы (Поля INCLUDE):** Позволяют добавлять неключевые атрибуты в листья некластерного индекса, исключая операцию `Key Lookup` (обращение к странице данных).

### Пример создания таблиц и индексов:
```sql
-- Таблица с кластерным индексом (Primary Key по умолчанию)
CREATE TABLE Users (
    UserId INT IDENTITY(1,1) PRIMARY KEY,
    Age INT,
    Details CHAR(100)
);

-- Создание обычного некластерного индекса
CREATE NONCLUSTERED INDEX IX_Users_Age ON Users(Age);

-- Создание покрывающего индекс посредством INCLUDE
CREATE NONCLUSTERED INDEX IX_Users_Age_Inc ON Users(Age) INCLUDE (Details);
```

## 3. Алгоритмы соединений (Join Algorithms)

| Алгоритм | Оптимален для | Особенности |
| :--- | :--- | :--- |
| **Nested Loops** | Малых наборов данных, предпочтительно с индексом по ключу соединения | Вложенные циклы: для каждой строки внешней таблицы ищется совпадение во внутренней. Не использует tempdb. |
| **Merge Join** | Средних и крупных упорядоченных наборов | Требует сортировки входных данных по ключу слияния. Сохраняет порядок. |
| **Hash Join** | Крупных неотсортированных наборов | Блокирующий оператор (только на фазе Build). Активно использует оперативную память и tempdb при сбросе данных на диск. |

## 4. Жизненный цикл запроса и сбор статистики
1. **Parse** (Разбор синтаксиса) → 2. **Bind** (Проверка объектов и метаданных) → 3. **Optimize** (Генерация оптимального плана по стоимости) → 4. **Execute** (Выполнение).

### Инструменты анализа плана и статистик:
```sql
-- Просмотр текстового плана выполнения запроса
SET SHOWPLAN_TEXT ON;
GO
SELECT * FROM Users WHERE Age = 25;
GO
SET SHOWPLAN_TEXT OFF;

-- Просмотр гистограммы распределения данных (статистики)
DBCC SHOW_STATISTICS ("dbo.Users", "IX_Users_Age");
```

### Мониторинг кэшированных планов из DMV:
```sql
SELECT TOP 50
    SUBSTRING(qt.text, (qs.statement_start_offset/2)+1,
        ((CASE qs.statement_end_offset
            WHEN -1 THEN DATALENGTH(qt.text)
            ELSE qs.statement_end_offset
          END - qs.statement_start_offset)/2)+1) AS [Sql],
    qs.execution_count AS [Exec Cnt],
    (qs.total_logical_reads + qs.total_logical_writes)/ qs.execution_count AS [Avg IO],
    qp.query_plan AS [Plan],
    qs.total_logical_reads AS [Total Reads],
    qs.last_logical_reads AS [Last Reads]
FROM sys.dm_exec_query_stats qs WITH (nolock)
CROSS APPLY sys.dm_exec_sql_text(qs.sql_handle) qt
CROSS APPLY sys.dm_exec_query_plan(qs.plan_handle) qp
ORDER BY qs.last_execution_time DESC
OPTION (recompile);
```

## 5. Транзакции, ACID и блокировки
* **Atomicity (Атомарность):** Всё или ничего.
* **Consistency (Согласованность):** Сохранение ограничений целостности и бизнес-правил.
* **Isolation (Изолированность):** Параллельные транзакции логически не влияют друг на друга.
* **Durability (Устойчивость):** Результат зафиксирован и устойчив к системным сбоям.

### Уровни изоляции и типы блокировок:
1. **Read Uncommitted:** Разрешены грязные чтения. При чтении ничего не блокирует и никого не ждет.
2. **Read Committed:** Чтения только зафиксированных данных. Ждет освобождения `Exclusive Lock`. При повторном чтении данные могут измениться.
3. **Repeatable Read:** При чтении ставит `Shared Lock` до конца транзакции. Данные строк не изменятся, но могут появиться фантомные записи.
4. **Serializable:** Полная сериализация. Накладывает блокировки на диапазон значений (`Key-Range Lock`) на основе условий запроса.
5. **Snapshot (MVCC):** Управление версиями строк. Читатели не блокируют писателей, а писатели — читателей. Исключает аномалии грязных, повторных и фантомных чтений, но подвержен аномалии **write-skew** (когда параллельные транзакции изменяют разные строки, нарушая общее ограничение целостности).

### Пример управления уровнями изоляции и транзакциями:
```sql
-- Включение Snapshot Isolation на уровне базы данных
ALTER DATABASE CurrentDB SET ALLOW_SNAPSHOT_ISOLATION ON;
ALTER DATABASE CurrentDB SET READ_COMMITTED_SNAPSHOT ON;

-- Применение внутри сессии
SET TRANSACTION ISOLATION LEVEL REPEATABLE READ;

BEGIN TRANSACTION;
    UPDATE Users SET Details = 'Updated details' WHERE UserId = 1;
COMMIT TRANSACTION;
```
